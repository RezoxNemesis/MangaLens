# Real site extraction and download request context

The Android APK bundles `io.github.junkfood02.youtubedl-android:library:0.18.1` from Maven Central. This packages the local yt-dlp extractor runtime, Python and QuickJS; no paid API, server proxy or companion app is required. Native libraries must be extracted (`android:extractNativeLibs="true"`). Existing ARM64/x86_64 APK splits keep other ABI payloads out of the download.

Source and licence: https://github.com/yausername/youtubedl-android (GPL-3.0). Include that dependency's licence/source attribution when distributing the APK. The library includes other components with their own notices.

`MediaLinkResolver` resolves direct media, MIME-identified opaque signed URLs and accessible HTML video/manifest links. Known social providers use the site extractor first; unresolved webpages use it as a fallback. A player thumbnail is not treated as a successfully downloaded video. The extractor disables user config and playlists, bounds socket retries, and has a 90-second process watchdog. Coroutine cancellation interrupts the extractor and destroys its native process. It selects an available combined audio/video representation at the requested height, falling back to the lowest combined format when no format fits the height ceiling. Split video/audio streams are deliberately rejected; separate-track 4K merging is not implemented in this build. UI quality choices are preferences, not guarantees.

Request headers and source webpage are stored in app-private per-download metadata rather than WorkManager data or logs. Progressive downloads and adaptive manifests/segments both apply the existing request-context security policy on every network hop. Captured cookies are valid only for the exact captured media URL. Legitimate browser-jar cookies are looked up for each actual redirect/segment URL, allowing authenticated segments while retaining domain/path/secure scoping. Referer/Origin are suppressed on HTTPS-to-HTTP downgrades; unrelated credential headers are discarded. These metadata survive pauses, process restart and retry. Removing a download removes its context. A failed download can re-resolve its original webpage to replace an expired signed URL; partial progressive data is then reset to avoid combining representations.

Accessible MP4/WebM files publish to Android Downloads; HLS/DASH use durable Media3 offline cache and play through the existing offline player. They are not exported as falsely labelled MP4 files. DRM, CAPTCHA, paywalls and inaccessible private/login-only media are not bypassed. Host support depends on the bundled extractor version and the site's current responses; internet-wide or permanently reliable support cannot be promised.

JVM fixtures cover native extractor JSON, rejection of DRM and audio-only/separate-track sources, opaque URL MIME detection, real extractor fallback routing, thumbnail rejection and cookie exclusion on redirects/segment requests. Native execution and live social-host coverage require separate Android/network verification.
