# Resource governor

The current candidate adds a real execution policy at shared native admission, chapter OCR page boundaries, saved subtitle windows, decoded speech windows and original provider-caption cue translation. It preserves task/model/source/owner/generation checks and the existing live speech wall-clock budget. It never cancels an active native call in response to pressure.

| Confirmed observation | Execution behavior |
|---|---|
| ActivityManager low-memory report, running-critical trim, or platform thermal CRITICAL / EMERGENCY / SHUTDOWN | Stop new computation at its next safe boundary. Durable chapter/subtitle tasks remain QUEUED with their existing generation, completed checkpoints and an explicit resource-wait reason. |
| Memory near the platform threshold, running-low/moderate trim, thermal MODERATE / SEVERE, power saving, or battery at most 15% while known unplugged | Background work rests for two seconds before admission and after its previous native completion. Live/interactive work remains eligible. |
| Known recovery | Hold the lower pressure for 15 seconds before reopening work. Escalation is immediate. |
| Unavailable reading | Keep an observed condition; never invent a cool thermal report or treat battery temperature as CPU temperature. An initially unknown device retains the existing runtime safeguards. |
| Module-owned cleanup | Bypass resource pauses while retaining the one-active-native-lease rule and waiting for actual native return. A full bounded queue is retried by the existing conflated cleanup scheduler. |

Admission permits at most 64 waiting calls and one active call. FIFO order remains within priority; a background waiter older than ten seconds gets a turn ahead of newer interactive requests when live/cleanup requests are absent. Live requests retain priority to protect their unchanged budget. A resource-delayed background request cannot block an eligible live request. Cancellation and an invalid captured generation remove their waiter without freeing another call's lease.

Chapter refinement now carries its exact task/owner/configuration/full-source receipt into native admission. The guard rejects paused, cancelled, deleted and replaced work and rechecks owner control after any suspending validation. Source queue polls do not hash files. A delayed entry performs one bounded SHA check, compares the app-owned atomic file identity before and after reading, then checks authority again. Existing page-source verification and completion fencing remain in place; refinement retains its captured model, style and target language.

After suspending feature validation, native entries recheck confirmed critical pressure without suspending or starting another duty-cycle wait while holding the lease. The check covers speech wrappers, actual asynchronously dispatched speech inference, live speech inference, Orez model loading and generation. Cleanup bypasses this resource check. A rejected entry releases its lease; an opened live invocation still performs its cleanup. Existing speech wall-clock budgets are unchanged.

`AndroidResourceSignalMonitor` is installed once for the application's lifetime. It observes protected battery/power broadcasts, API 29+ platform thermal reports and ActivityManager memory every two seconds while the process can run. API 26/28 thermal reports stay unavailable. The monitor needs no new permission or wake lock. Memory pressure emits a typed bounded event hint; the governor and durable native journals remain authoritative.

Resource deferral is distinct from user PAUSED. The store accepts it only for the current QUEUED/RUNNING generation. Workers return WorkManager retry with linear ten-second minimum backoff, instead of returning successful completion or generating a new identity. Existing startup recovery also restores eligible jobs. Android scheduling and accumulated retry backoff can delay recovery; this change promises durable eventual eligibility, not an immediate background wake or immunity from platform force-stop. Explicit user pause/cancel/replacement stays fenced and never resumes from resource recovery.

Current verification: actual-source standalone Kotlin/JUnit slices compiled and passed 39 compute/cleanup/live-budget tests, 40 chapter journal tests and 46 subtitle journal tests. Those totals include meaningful initial RED evidence for the missing queue cap, resource policy and durable resource outcome. The expanded policy checks cover pressure hysteresis, unknown signals, foreground progress, cleanup ownership, queue overflow, stale/cancelled waiters and checkpoint persistence. Source manifests and executed logs are stored in the candidate evidence archive. Coordinated Android build, direct UI/WorkManager recovery, real thermal/memory hardware and native model accuracy remain separate acceptance gates.

The later native-entry candidate passed eight real-journal held-queue tests after all eight failed with the missing guard, and 39 focused admission/policy/live-budget tests after held proof and live pressure escalation regressions failed. These later source snapshots are separate from the sealed integrated build2. They establish captured authority and controlled-signal effect boundaries; they do not establish JNI/model output quality, Android UI success or physical-sensor behavior.

Settings now renders the policy snapshot in Device resources, including explicit unavailable thermal readings. `ResourceGovernorAcceptanceTest` contains three direct Android acceptance methods for actual Settings reachability and scoped controlled-signal card/admission recovery. These methods are authored and pending coordinated APK/device execution; they do not inject or claim physical sensor measurements.
