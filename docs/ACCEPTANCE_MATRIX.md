## Execution rules

1. Major upgrades require the full feasible core-screen regression plus deeper changed-area tests in Codex Cloud and a real Android emulator. Unit tests and AndroidTest compilation do not satisfy this gate.
2. Invoke the exact shipped UI controls and assert requested results/artifacts. Direct worker/backend calls alone cannot prove buttons/navigation/state wiring.
3. Preserve data for upgrade/migration tests; clean installs and retained-data upgrades are separate cases. Distinguish ordinary process interruption from Android force-stop.
4. Use controlled local HTTP/HTTPS/web/media fixtures with known bytes, metadata and failure points. Keep genuine permitted-provider smoke and real-model quality tests distinct from mocks.
5. Record PASS/FAIL/BLOCKED/SKIPPED with candidate/fixture/report/output identity. A test skipped by an assumption because a private sample/model is absent cannot be reported as passed.
6. For failures, retain screenshot/logcat/trace and exact stage; repair and rerun affected checks plus core smoke. Do not rerun unrelated already-passing suites without a new reason.
7. Measure defensible resource/performance baselines. Emulator codecs/thermal signals cannot establish every real ARM64/GPU/NPU/hardware behavior.
8. Finish a reviewable candidate and mandatory evidence before external release/merge; the parent owns source, artifacts, branch/PR updates and any final release authorization.

Contract references use `A` for original Appendix A sections and `M` for current mission sections; scenario IDs map those contracts to concrete acceptance actions.
